# 사진첩 자료 조사 1차

후속 결정: 사용자가 P05(2011년 사진첩)를 내부 구성의 기준으로 명시적으로 채택했다. 따라서 아래의 후기 자료 제외 원칙은 최초 조사 당시의 판단 이력이다. 현재는 외곽 master 유지 + P05 내부 구성으로 진행한다. [구현 기준](verification/photos-step2/README.md)을 참고한다.

조사일: 2026-09-13. 범위는 실제 사진첩 자료의 확보·판독과 후속 복원의 기준 정리다. 앱 화면, Config, 로그인, 작성·댓글 저장 기능은 변경하지 않았다.

## 결론

**2006년 운영사 사진첩 캡처는 확보했지만, master와 동일한 테마의 일반 사진첩을 댓글 하단까지 보여 주는 자료는 아직 확보하지 못했다.** 따라서 이번 결과는 자료 조사와 잠정 구조 명세이며, 사진첩 전체의 픽셀 명세 확정은 아니다.

- 외곽 프레임·바인더·우측 탭·전체 배율은 계속 [master](../references/cyworld-master.png)를 따른다. 다른 스킨의 치수를 옮기지 않는다.
- 2006년 자료는 당시 사진첩의 존재·화면 구성에 대한 직접 근거다. 다만 일반 폴더 목록이 아니라 **태그 탐색 상태**다.
- 선명한 2009·2011년 캡처는 후기 비교 자료다. 읽기 쉽다는 이유로 원본 시기의 명세로 승격하지 않는다.
- 댓글 행·입력칸, 일반 폴더의 선택 표시, 제목 영역의 정확한 폰트는 미확인이다. 추측한 UI를 복원 사실처럼 기록하지 않는다.

master의 연대 자체도 엄밀한 2008년 이전으로 확정되지 않는다. 기존 [HOME 조사](reference-research.md)의 미니라이프 관련 주의사항을 유지한다. 여기서 목표는 master의 외관 유지와 후기 개편 요소의 무분별한 혼입 방지다.

## 2006년 직접 관찰

운영사 발표는 사진의 인물에 태그를 붙여 홈피로 연결하거나 알림을 보내는 기능을 설명한다. [발표 원문](https://www.newswire.co.kr/newsRead.php?no=163944)

P01에서 보이는 사항:

- 좌측은 프로필 사진 대신 `PHOTO ALBUM / 태그`와 목록이 들어간 좁은 영역이다. `최근등록태그`, 사람 이름 등의 항목, `내 태그 보기`, 아래 `폴더관리하기`가 보인다. **이 목록을 일반 사진 폴더라고 해석하면 안 된다.**
- 우측은 큰 사진 한 장과 아래의 태그·작업 링크가 세로로 이어지는 영역이다. 오른쪽 가장자리에 세로 스크롤바가 있다.
- 네 개의 바인더 고리와 외부 세로 메뉴를 유지하면서 내부 내용만 바뀐다. 현재 저장소의 좌·우 뷰 교체 구조와 양립한다.
- 사진 위 이름·수정/삭제·아이콘과 빨간 번호 1~5는 태그 기능 및 보도자료 설명 요소다. 일반 사진첩의 고정 장식으로 복제하지 않는다.
- 사진 상단의 게시물 제목·작성 정보와 댓글 영역은 이 캡처로 확정할 수 없다. 제목이 원래 없다는 뜻도 아니다.

P02는 태그 오버레이의 확대 예시다. P03은 이름·사진 제목·날짜가 있는 태그 알림 표이며 일반 앨범 목록으로 사용하지 않는다.

### P01의 대략적인 영역

아래는 이미지 좌상단 기준 `(x, y, width, height)` 육안 판독값, 경계 오차 약 ±3px이다. **앱 CSS 값이 아니다.** JPEG 압축과 스킨 차이 때문에 정밀 색·글꼴 계측에는 사용하지 않는다.

| 영역 | P01 관측값 | 용도 |
| --- | --- | --- |
| 좌측 패널 | 22, 39, 126, 285 | 왼쪽 탐색 영역의 존재 확인 |
| 우측 패널 | 158, 40, 341, 285 | 본문과 스크롤의 분리 확인 |
| 사진 | 176, 52, 307, 225 | 사진을 본문의 주된 폭으로 표시하는 사례 |
| 세로 스크롤바 | 482, 47, 12, 271 | 스크롤 위치 확인 |

사진의 오른쪽과 스크롤바가 가까워 경계가 일부 겹쳐 보인다. 이를 근거로 정확한 padding이나 원본 이미지 표시 폭을 역산하지 않는다.

## 후기 자료에서 구분할 것

### 2009년: 게시물 내부는 선명하지만 시기가 다름

P04에는 회색 제목 띠, 왼쪽 작성자, 오른쪽 날짜·스크랩 수, 사진, 설명, 공개설정이 세로로 보인다. 제목 우측 `주소복사`와 사진 아래 `크게보기`에는 작성자가 빨간 상자를 그렸다. 빨간 윤곽은 UI가 아니다. 댓글은 아래가 잘려 보이지 않는다. [출처](https://xarsrima.tistory.com/661)

같은 작성자의 [2009-02-04 기록](https://xarsrima.tistory.com/648)은 사진첩의 주소복사 버튼을 새로 발견했다고 설명한다. 이는 그날의 사용자 관찰이지 공식 배포일 확정은 아니다. 이번 목표 화면에 해당 버튼을 기본으로 넣을 근거로 사용하지 않는다.

2월 25일 글의 사진 폭 `400 → 580`은 **작성자의 전망**이다. 580px로 개편되었다는 확정 사실이나 지금 앱에 적용할 치수가 아니다.

### 2011년: 일반 폴더와 넓은 보기의 비교

P05에는 그룹 제목·폴더 아이콘·구분선이 있는 왼쪽 목록, 오른쪽 폴더 설명과 보기 방식, 게시물 제목·정보·사진이 보인다. 소유자용 수정·사진올리기 버튼도 포함되어 있다. 이 상태를 방문자 화면과 섞지 않는다. P06은 왼쪽 목록 없이 본문이 넓어진 상태이므로 현재 2패널 배치의 기준으로 삼지 않는다. 튜토리얼의 테두리 강조 역시 서비스 UI가 아니다. [출처](https://unsungbyul.wordpress.com/2011/10/16/tutorial-cyworld-photos-photo-albums-2011/)

2011년 화면의 폴더 구조·보기 옵션·글꼴이 모두 2006년에도 같았다고 소급하지 않는다. 레이스·호피 스킨, 폰트, 넓은 보기, 후기 부가 영역은 이식하지 않는다.

## 다음 구현을 위한 잠정 구조

여기부터는 관측 사실이 아닌 **현재 프로젝트를 위한 제안**이다. 세부 복원 근거가 없는 부분은 구현 이후에도 잠정임을 표시해야 한다.

| 영역 | 유지하거나 준비할 구조 | 확정 수준 |
| --- | --- | --- |
| 공통 외곽 | 579 × 349 캔버스, 프레임·바인더·탭 | 기존 HOME 명세 유지 |
| 왼쪽 | 사진첩 제목, 폴더 탐색용 내용 영역 | 용도만 잠정 결정. 일반 폴더의 행·선택 표시 미확정 |
| 오른쪽 | 제목 → 작성 정보 → 사진 → 설명 → 댓글 영역 | 구현 후보 순서. 후기 관찰과 요구사항을 조합한 것으로 동시대 전체 검증 아님 |
| 사진 | 가로폭 안에 원래 비율로 표시, 둥근 모서리·그림자 없음 | 프로젝트 선택. 사진 자체를 카드로 만들지 않음 |
| 스크롤 | 본문이 프레임 밖으로 커지지 않고 내부에서 세로 이동 | 위치는 기존 명세, 실제 동작은 후속 구현 |
| 댓글 | 이름·내용·날짜·입력칸을 위한 공간 | 요구사항만 존재. 배경색·행간·버튼 배치 미확정 |

기존 패널은 왼쪽 `(36, 68, 112, 240)`, 오른쪽 `(150, 68, 279, 240)`을 유지한다. HOME의 본문 폭 240px과 스크롤 위치는 출발점일 뿐 사진첩 원본 치수로 확정하지 않는다. 적용값은 [기존 Visual Spec](visual-spec.md)의 최신 보정과 대조한다.

폰트 역시 정확한 원본 서체가 확인되지 않았다. 폴더 이름, 게시물 제목, 작성 정보, 댓글을 각각 비교 대상으로 나누고 탭의 `scaleX(.92)`를 본문에 일괄 적용하지 않는다. `Galmuri`는 기존 대체 폰트이며 원본이라는 주장을 하지 않는다. 자간·행간·굵기는 선명한 같은 계열 자료가 확보된 뒤 결정한다.

## 남은 조사와 진행 판단

정확한 복원 판정을 위해 우선 필요한 자료는 **일반 폴더 목록, 게시물 상단, 댓글 하단이 각각 읽히는 2008년 이전의 같은 계열 2패널 화면**이다. 관리자로 접속했는지, 글 작성자와 방문자 중 누구인지, 확대 보기인지도 함께 확인해야 한다.

다음 정적 구현은 공통 외곽을 보존한 사진 중심의 잠정 화면까지 진행할 수 있다. 다만 댓글 모양과 일반 폴더의 세부 수치를 정확한 복원으로 확정하기에는 현재 근거가 부족하다. 2011년의 선명한 화면으로 빈 근거를 조용히 채우지 않는다.

이미지와 사진 속 인물·게시물 내용은 조사 목적으로만 보관한다. 공개 배포용 자산으로 복사하지 않는다. 후속 샘플 사진은 별도로 사용 권한이 확인된 것을 준비한다.
