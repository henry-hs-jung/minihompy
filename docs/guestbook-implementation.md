# 방명록 정적 구현

G01 기준을 사용자 승인 후 적용. G02는 다른 테마의 별도 구조가 아니라 공개글 상태를 확인하는 보조 자료로 취급한다.

## 범위

- `views/guestbook.js`: HOME의 좌측 프로필 생성기를 재사용하고, 오른쪽에 작성 영역과 방명록을 렌더링한다.
- `guestbook-data.js`: 공개 2건·비공개 1건의 가상 샘플과 댓글. 데이터는 textContent로 삽입한다.
- 공개·비공개는 동일한 글 구조. 비공개는 연한 노란 제목줄과 안내를 추가한다.
- 상단 작성 영역, 미니미, 번호·이름·집 아이콘·날짜, 본문, 댓글과 입력줄을 작은 고정 레이아웃으로 배치했다.
- 본문 240px, 미니미 칸 56px, 본문 글씨 7px/10px, 댓글 6px/9px, 날짜 5px/9px. 글씨와 색은 원본 CSS가 아닌 축소 캡처 기반 근사값이다.
- 기존 HOME의 미니미 스프라이트를 재사용했다. G01의 개별 의상·배경까지 재현한 것은 아니다.
- 작성·댓글·관리 버튼은 비활성. 스크롤은 휠·터치·화살표·트랙 클릭·드래그·키보드로 동작한다.
- 페이지 하단 자료가 부족하므로 페이지 번호나 페이지당 글 수는 임의로 확정하지 않았다.

## 비공개 샘플 주의

`visibility: 'private'`는 열람 권한이 있는 화면의 시각 상태일 뿐이다. 실제 접근 제어가 없으며 정적 JS의 모든 내용은 공개적으로 읽을 수 있다. 실명 방문자의 비밀글이나 실제 비공개 데이터는 넣지 않는다. 추후 저장 개발 때 서버 측 권한 검증을 별도로 구현해야 한다.

## 검증

`scripts/verify-guestbook.mjs`: 데스크톱 1000×700, 모바일 375×812의 DPR 1·2. 공개/비공개, 좌측 config 반영, 비활성 작성, 스크롤, 재진입, 긴 이름·본문·댓글, HTML 텍스트 처리, 빈 목록과 리소스 오류 검사.

캡처와 실행 결과: [guestbook-step2](verification/guestbook-step2/). 모바일에서는 기존 정책대로 579px 캔버스를 유지하고 가로 스크롤한다.

`scripts/verify-navigation.mjs`의 방명록 예상값을 실제 뷰로 갱신. 15개 탐색 시나리오와 기존 9개 메뉴 HOME 캡처의 픽셀 동일성 통과.

실행 예:

```sh
CHROMIUM_PATH=/path/to/chromium node scripts/verify-guestbook.mjs /path/to/playwright/index.mjs
```
