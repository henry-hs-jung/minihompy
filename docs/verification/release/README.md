# 통합 검수

검수 대상: 관리자/방문자 권한, 메뉴별 저장 흐름, 네트워크 실패와 초안, 공개/비공개 방명록 및 댓글, 고정형 화면 회귀.

최종 결과: 2026-09-13 수정본 기준 **19/19 검사 스크립트 통과**. 실제 Supabase의 10개 테이블 공개 조회 및 프로필 조회도 통과했다. 검수 중 운영 데이터 쓰기는 0건이다. 사용자가 010 SQL의 운영 적용 성공을 확인했다. 적용 후 실제 게시판 신규 저장은 사용자 브라우저에서 확인한다.

## 재실행

```sh
CHROMIUM_PATH=/path/to/chromium node scripts/verify-release.mjs /path/to/playwright/index.mjs /path/to/pglite/index.js
CHROMIUM_PATH=/path/to/chromium node scripts/verify-release-live-read.mjs /path/to/playwright/index.mjs
```

첫 명령은 20개 검사 스크립트(배율 검사 포함)를 순차 실행하고 `results.json`에 결과와 각 검사 출력을 기록한다. 로컬 PGlite 및 모의 API 기반이다. 댓글 DB 검사는 001~010 마이그레이션을 모두 같은 DB에 적용한 뒤 부모 글과 댓글 권한을 검사한다. 두 번째 명령은 새 브라우저에서 실제 Supabase의 GET만 허용하고 10개 테이블과 프로필 저장소 모듈의 공개 조회 결과를 `live-read.json`에 기록한다. 사용자 본문은 기록하지 않는다.

정적 복원 초기의 `verify-integration.mjs`는 현재 DB 구조에 맞지 않는 가정이 있어 이번 기능 통합 검사에 사용하지 않는다. HOME 픽셀/탭/탐색 회귀는 현재 `verify-navigation.mjs`로 검사한다.

## 검사 범위

- 식별: 읽기만 할 때 익명 계정을 생성하지 않음, 닉네임 공유, 관리자/방문자 세션 분리, 조작된 user_metadata로 관리자 권한 획득 불가, 인증 실패 시 쓰기 차단.
- 권한: 일반 방문자의 관리자 글 생성 금지, 작성자 수정/삭제, 관리자 삭제, 비공개 방명록 조회 범위 및 공개에서 비공개로의 단방향 전환, 부모 비공개 전환 시 댓글 접근 차단.
- 저장: CRUD, 새로고침 후 재조회, 폴더 이동과 페이지, 동시 수정 충돌, 저장/업로드 응답 유실 후 재시도, 입력 유지, 모드/메뉴 이동, 권한 상실 시 화면 정리.
- 파일: 허용 형식/크기와 공개 사진 참조 보호, 사진첩 인라인 미리보기, 프로필 사진 미리보기 및 교체/제거.
- 화면: 메뉴별 데스크톱/375px 모바일 캡처, 긴 본문과 스크롤, 본문 HTML 비실행, 미확인 프로필 메뉴 공백, 15개 메뉴 탐색 시나리오와 HOME 기준 픽셀.

## 이번 보완

1. 게시판 신규 저장 응답을 잃은 뒤 다시 제출하면 중복 글이 생길 수 있었다. 초안별 UUID를 재사용하고 저장된 동일 내용 확인을 추가했다. ID의 유일성은 DB 기본키가 보장한다. `202609130010_board_retry.sql`로 ID INSERT 열 권한을 추가해야 한다. 기존 관리자 전용 RLS는 변경하지 않는다.
2. 게시판은 로그아웃 뒤 저장 버튼만 비활성화하고 초안을 계속 표시했다. 다른 편집기와 동일하게 초안을 제거하고 늦은 저장 응답의 화면 반영도 차단했다. 동일 관리자의 토큰 갱신에서는 초안/포커스를 유지한다.

두 항목에 회귀 검사를 추가했다. 저장 요청이 서버에 도착한 뒤 로그아웃하는 경우 이미 수행된 DB 쓰기까지 취소하는 것은 아니다.

## 운영 확인과 한계

- 운영 DB 쓰기/삭제, 파일 업로드, 신규 익명 계정 생성은 수행하지 않는다. 관리자 및 실제 방문자 쓰기는 사용자의 브라우저에서 확인해야 한다.
- 공개 조회 성공만으로 운영 RLS의 모든 인증 경로를 입증하지 않는다. 세부 권한은 저장소 SQL의 로컬 실행으로 검사한다. 운영 프로젝트의 대시보드 설정/수동 변경 전체를 감사한 것은 아니다.
- 실제 프로젝트에 공개 게시판 글이 없어 댓글의 해당 부모 실조회는 건너뛰었다. 게시판 댓글은 로컬 DB와 모의 API로 검사했다.
- 비공개 전환은 이후 조회를 제한한다. 이미 전달된 공개 본문/이미지 또는 외부 캐시를 회수하지 않으며 실시간 동기화도 지원하지 않는다.
- CAPTCHA 미사용은 사용자 결정이다. 익명 UID별 작성 제한이 있어도 새 식별자를 반복 생성하는 남용까지 막지는 못한다. 브라우저 데이터 삭제 시 방문자 본인 수정 권한도 잃는다.
- 실패한 사진 저장 후 미참조 파일이 남을 수 있다. 자동 고아 파일 수집은 범위 밖이다.
- Chromium 자동화/모바일 뷰포트 검사이며 실제 모바일 기기, Safari/Firefox 및 GitHub Pages 배포 환경은 별도 확인이 필요하다.
