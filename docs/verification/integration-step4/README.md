## 검증 범위

메뉴 설정 다섯 사례 × 세 viewport로 15개 조합을 검사했다. 표시/숨김/순서, 홈 숨김, 전체 숨김, 중복·잘못된 ID, 연속 탭 배치, 선택 시 크기 불변, 두 영역 동시 전환, Enter·뒤로/앞으로·새로고침·직접 주소 및 잘못된 주소 복구를 확인했다.

문구는 현재값·긴 한글/공백 없는 영문 혼합·빈 값·잘못된 타입의 네 사례를 579×349, 1280×800, 375×812(DPR 1), 320×740(DPR 2)에 적용해 16개 조합을 검사했다. 고정 캔버스, 말줄임 영역, 전체 문구 툴팁, 최근게시물 세 줄 제한, 우측 이름 배지와 일촌신청 자리 보존, 가로 스크롤, 메뉴 복귀 후 재적용·중복 없음, 로컬 리소스 오류 없음을 확인했다.

Config 회귀 검사는 이름 두 위치 동기화, 숫자·문구 변경, 빈 문자열, 줄바꿈, HTML 형태의 문자열을 실행하지 않는 동작, 잘못된 타입의 기존값 유지, 새 한글 확장 폰트 로딩, 외부 요청 없음과 메뉴 설정 적용을 확인했다. 임시 파일 묶음을 사용하며 원본 설정은 덮어쓰지 않는다.

기존 짧은 문구와 아홉 메뉴로 구성한 HOME은 작업 7 캡처와 파일 내용이 동일하다. 현재 화면·긴 문구 화면·모바일 DPR 2 캡처를 열어 육안 확인했다. 제목·프레임·탭을 현대식으로 확대하지 않았고, 넘치는 문구만 말줄임한다.

## 결과와 한계

세 글자 이름이 우측 관계 영역을 넘던 문제를 해결했다. 이름 원문은 유지하고 최대 14px로 표시해 뒤의 관계 배지를 보존한다. 기타 편집 문구도 [설정 안내](../../configuration.md)의 역할별 폭·줄수 규칙을 따른다. 방문자 수는 0 이상 안전한 정수만 허용하며 잘못된 값은 현재값/기본값을 유지한다.

사진첩·방명록의 실제 내부 화면, 작성·저장, 관리자 UI, 인증·Supabase, 배포는 구현하지 않았다. 모바일 검사는 Chromium의 viewport/DPR 검사이며 실제 터치 기기나 Safari·Firefox 검증은 아니다. 원본 폰트와 개별 GIF를 확보한 것은 아니며 기존 시각 복원의 차이는 남는다. 미래에 추가할 요소는 별도의 배치·문구 제한 및 테스트가 필요하다.

## 재실행

```sh
node scripts/verify-integration.mjs /path/to/playwright/index.mjs
```

내부적으로 navigation 및 config 스크립트를 실행한 뒤 문구 통합 검사를 실행한다. 결과는 이 폴더에만 기록한다. HOME이 숨겨진 사용자 설정은 current 사례에서 선택 화면을 캡처하고 HOME 문구 검사만 건너뛴다. 별도 긴 문구·빈 값·잘못된 값 사례는 HOME을 명시적으로 표시해 검사한다. 단일 메뉴는 타 메뉴 왕복만 생략한다.
