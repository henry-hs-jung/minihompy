# 사진첩 정적 화면

후속 [마무리 검수](../photos-review/README.md)에서 다중 사진, 긴 구분선 말줄임, 10페이지 묶음 이동을 보완했다. 아래 잠정 댓글 디자인은 이후 사용자 승인으로 프로젝트 기준이 되었다. 원본 역사적 정확성에 대한 한계는 그대로다.

## 적용 기준

사용자가 [P05](../../../references/photos/2011-album.png)를 사진첩 내부 기준으로 지정했다. 2011년의 레이스 스킨과 넓어진 프레임을 옮기는 것이 아니라, 기존 master의 외곽에 내부 배치를 맞추는 작업이다.

- 캔버스 579 × 349px, 왼쪽 패널 `(36,68,112,240)`, 오른쪽 패널 `(150,68,279,240)` 유지.
- P05 본문 폭 400px에 대응하여 사진 폭 240px 사용. 사진은 원래 비율로 표시하며 크롭·둥근 모서리·그림자 없음.
- 왼쪽: PHOTO ALBUM 제목, 작은 태그 표시, 분홍 배너, 폴더 및 구분선, 하단 관리 문구. 폴더는 중첩 없이 한 단계이며 선택 시 게시글 교체.
- 오른쪽: 폴더 설명, 전체공개 상태와 글 수, 펼쳐보기 표시, 회색 제목 띠, 작성자·날짜·스크랩 수, 사진, 본문, 댓글, 페이지 번호.
- 폴더 글을 두 개씩 표시하며 하단 페이지 번호로 전환. 전환 시 내부 스크롤을 맨 위로 초기화.
- 세로 스크롤바는 9px 너비의 고정 스타일. 휠·터치·화살표 버튼·트랙 클릭·드래그·키보드 이동 지원. 운영체제의 숨김 스크롤바에 외형을 의존하지 않음.
- 7px 본문, 6~6.5px 보조 정보, Arial 숫자와 영문 표제. 기존 Galmuri 대체 폰트를 사용하며 원본 폰트 복구는 아님. 자간은 0, 탭 전용 가로 축소는 적용하지 않음.

## 의도적인 차이와 한계

원본 캡처의 광고 이미지 대신 분홍 배너와 작은 꽃 표시를 사용했고, 사진은 로컬 풍경 샘플이다. 일반 폴더 선택 강조는 잠정 표현이다. 댓글·입력칸·페이지 번호는 참고 이미지에 보이지 않는 하단의 잠정 디자인이며 정확한 복원을 주장하지 않는다.

소유자 수정·사진올리기와 주소복사 버튼, 체크박스는 표시하지 않았다. 태그·보기 방식·폴더관리·와이드형은 시각 표시만 있으며 버튼으로 가장하지 않는다. 댓글 확인 버튼과 입력칸은 비활성이다. 작성·로그인·저장·Supabase는 구현하지 않았다.

## 데이터 및 코드

- [photos-data.js](../../../photos-data.js): `folders`의 폴더 항목과 `{ type: 'divider', label: '...' }` 구분선. `posts`는 `folder` ID로 연결하고 `pageSize`로 페이지당 글 수 지정.
- [views/photos.js](../../../views/photos.js): 기존 뷰 등록 방식으로 좌측·본문 생성. 문구를 `textContent`로 처리. 선택 폴더와 페이지는 메모리 상태로, 새로고침 시 초기화.
- [styles.css](../../../styles.css): 사진첩 전용 클래스. 기존 HOME 스타일 변경 없음.

## 검증

`verify-photos.mjs` 통과: 데스크톱 1000 × 700, 모바일 375 × 812, DPR 1·2. 이미지 로드, 프레임·사진 치수, 폴더·구분선, 빈 폴더, 페이지 이동, 댓글 비활성, 스크롤 버튼·키보드·드래그, HOME 왕복을 검사했다. 브라우저 오류와 실패한 요청은 없었다.

`verify-navigation.mjs` 통과: 기존 메뉴 설정 15개 시나리오, 표시 순서·숨김·키보드·뒤로/앞으로·새로고침. 기준 아홉 탭 HOME 캡처는 작업 7 이미지와 바이트 단위로 동일했다. 사진첩이 빈 화면이라는 이전 테스트 가정만 수정했다. 사용자 `config.js`는 변경하지 않았다.

스크린샷을 직접 확인했다. 작은 화면은 기존 정책대로 가로 스크롤하며 자동 축소하지 않는다. Safari·Firefox·실제 모바일 기기는 미검증이다.
