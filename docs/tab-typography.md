# 우측 탭 글자 재검토

대상은 작업 4의 `index.html`과 master의 홈·프로필·다이어리 등 우측 탭이다. 이번에는 분석 자료만 추가했으며 사이트 CSS와 HTML은 변경하지 않았다.

후속 적용: 사용자 요청에 따라 탭만 보정했다. 아래 분석은 변경 전 기록이며, 적용 결과는 이 문서 마지막 절을 참조한다.

## 결론

현재 탭과 원본의 차이가 확인된다. 주된 차이는 **대체 글꼴의 자형, 글자 폭, 작은 크기의 래스터화**다. 자간만 조절해서 해결할 문제로 판단하지 않는다.

- 현재 실제 폰트는 WenQuanYi Zen Hei다. CSS에 적힌 첫 후보인 돋움이 아니다.
- 원본의 비활성 탭 글씨는 현재보다 대체로 좁고, 약 6~7px의 가시 높이를 유지한다.
- 돋움·굴림 7px로 바꾸기만 해도 4글자의 advance 폭은 여전히 28px다.
- 6px 크기는 advance 폭을 24px로 줄이지만, 현대 브라우저의 아웃라인 렌더링에서는 획이 심하게 뭉개지거나 높이가 낮아진다.
- 12px 단색 글자 마스크를 절반으로 표시한 실험은 폭과 획 구조를 비교할 만한 후보였다. 그렇다고 원래 CSS가 12px였거나 캡처 배율이 50%였다고 확정할 수는 없다.
- **돋움·굴림 계열의 작은 비트맵 표현을 우선 검토할 근거는 생겼지만 정확한 원본 폰트는 미확정이다.** 이번 실험만으로 두 글꼴 중 하나를 확정하지 않는다.

## 비교 자료

[비교 화면](verification/tab-fonts/comparison.html) · [비교 스크린샷](verification/tab-fonts/comparison.png) · [측정 결과](verification/tab-fonts/results.json) · [재현 스크립트](../scripts/study-tab-fonts.mjs)

비교 화면은 왼쪽부터 master, R06, 현재 글꼴, 여러 돋움·굴림 후보를 배치한다. 탭 배경은 후보 전체에서 현재 CSS로 고정했으므로 원본 배경의 색·질감 차이를 글꼴 차이로 해석하지 않는다. 첫 두 열을 제외한 열은 브라우저에서 31 × 161px로 캡처한 결과를 4배 확대했다. 원본 이미지는 수정하지 않았다.

R06은 740px를 560px에 대응시키는 기존 추정 배율로 표시했다. 비교용 확대에는 최근접 표시를 사용하므로 원본의 정확한 축소 필터를 재현한 것은 아니다.

## 관측한 폭과 높이

같은 임계값으로 청록 바탕 위 밝은 글자 픽셀을 추출한 대략적 결과다. 탭 내부의 x·y 범위를 제한하고 RGB의 R > 100인 픽셀을 읽었다. 이미지 흐림과 압축으로 경계가 달라지므로 ±1~2px 정도의 관측 오차가 있다. 색 임계값을 높이면 master의 가는 획이 사라지는 것도 확인했다.

| 라벨 | master의 가시 획 폭 | 현재 화면의 가시 획 폭 |
| --- | ---: | ---: |
| 프로필 | 약 16px | 약 20px |
| 다이어리 | 약 22px | 약 26px |
| 쥬크박스 | 약 21px | 약 26px |
| 사진첩 | 약 16px | 약 20px |

master의 글자 높이는 이 범위에서 약 6~7px다. R06을 master 배율로 환산한 다이어리의 가시 폭은 약 22px로 같은 관측을 뒷받침한다. 가시 획 폭과 HTML 텍스트의 advance 폭은 다르므로 서로 같은 측정량으로 비교하지 않는다.

| 실험 | 다이어리 advance 폭 | 판단 |
| --- | ---: | --- |
| 현재 WenQuanYi 7px | 28px | 획 폭도 원본보다 넓음 |
| 돋움·굴림 7px | 28px | 폰트 교체만으로 폭 문제가 해결되지 않음 |
| 돋움·굴림 6px | 24px | 폭은 유리하나 작은 획 표현이 불안정 |
| 돋움·굴림 12px, transform 0.5 | 24px | 단순 transform만으로 비트맵 표현이 되지 않음 |
| 돋움 12px, transform 0.55 | 약 26.4px | 폭이 다시 넓어짐 |
| 단색 마스크 12px, 표시 배율 0.5 | 24px | 작은 획 구조를 비교하는 진단용 후보 |

세로 위치는 글꼴의 baseline·ascender와 line-height에 영향을 받는다. 같은 flex 중앙 정렬이어도 보이는 글자의 중심이 같지는 않다. 후보 간 높이가 달라서 이번에는 공통 y 보정값을 확정하지 않았다. 글꼴과 가시 크기를 결정한 뒤 라벨의 잉크 중심을 기준으로 조정해야 한다.

## 로컬 글꼴 확인과 실험의 한계

Linux의 기본 폰트 목록에는 돋움·굴림이 없지만 `/mnt/c/Windows/Fonts/gulim.ttc`는 존재했다. 해당 파일에서 Gulim, GulimChe, Dotum, DotumChe 네 face를 확인했다. Microsoft의 글꼴 목록도 이 파일과 가족 이름의 대응을 확인해 준다. 이는 싸이월드가 그 글꼴을 사용했다는 근거는 아니다. [Microsoft 글꼴 목록](https://learn.microsoft.com/en-us/typography/fonts/windows_10_font_list)

로컬 TTC에는 11~25px 크기의 EBDT/EBLC 비트맵 strike가 들어 있다. 이 파일은 현재 Windows에 있는 버전이며 당시 사용된 파일과 동일한 버전인지 확인하지 않았다.

원래 TTC와 비트맵 테이블이 포함된 TTF를 이 Linux Chromium 환경에서 시험했을 때 폰트가 선택되었다고 보고되지만 실제 글자가 빈 화면으로 나오는 문제가 있었다. 따라서 최종 아웃라인 비교에는 **임시 사본에서 EBDT/EBLC를 제거한 TTF**를 사용했다. 이 때문에 그 결과는 원래 Windows의 돋움·굴림 렌더링을 재현한 것이 아니다. 성공한 최종 방법과 한계는 결과 JSON에도 기록했다.

단색 비교는 원래 TTC를 FreeType/Pillow의 monochrome 모드로 읽어 나온 글자 마스크를 픽셀 사각형으로 표시한 진단용 실험이다. 당시 IE의 렌더링 또는 원래 비트맵 strike를 그대로 추출한 것으로 단정하지 않는다. 글자 마스크를 제품 UI에 적용하지도 않았다.

Windows 폰트는 임시 디렉터리와 브라우저 메모리에서만 사용하고 정리했다. 저장소에는 폰트 파일을 추가하지 않았으며 시스템 폰트 설치·설정도 변경하지 않았다. 스크립트 재실행에는 Playwright, Python의 fontTools·Pillow, 위 로컬 Windows 폰트 경로가 필요하다.

원본 탭이 텍스트였는지 글씨를 포함한 이미지 자산이었는지도 원래 HTML/CSS가 없어 확정하지 못했다. R06에서 보이는 밝은 글씨 주변의 어두운 픽셀을 실제 text-shadow로 단정하지 않는다. 이미지 축소와 배경색의 영향일 수 있다.

## 이후 글꼴 작업 기준

1. `letter-spacing: 0`을 유지한다. 원본 자간이 0이었다는 확증은 없지만 음수 자간을 넣어 넓은 대체 글꼴을 억지로 맞출 근거도 없다.
2. 탭의 목표는 가시 획 폭 약 16~17px(3글자), 21~23px(4글자), 높이 약 6~7px다. font-size 숫자만 맞추는 대신 이 결과를 확인한다.
3. 브라우저가 실제 사용하는 글꼴과 글리프 표시 여부를 함께 확인한다. computed font-family와 로딩 성공만으로 완료를 판정하지 않는다.
4. 탭, 본문, 굵은 제목, 작은 영문 카운터를 독립적으로 비교한다. 탭에 맞는 크기를 본문 전체에 일괄 적용하지 않는다.
5. 대체 글꼴의 굵기·가시 폭·획 높이·기준선을 결정한 다음 색과 명암을 보정한다. 전체 페이지를 흐리게 처리해 글자 차이를 감추지 않는다.

작업 3의 `tab: 7px / 9px`는 검증된 최종값이 아닌 첫 구현값으로 남긴다. 작업 5에서는 이 재검토 결과를 우선 반영해야 한다. 이번에 비교를 위해 생성한 SVG 글자 마스크는 분석 방법이며 제품의 텍스트 구현 방침을 바꾸는 결정이 아니다.

## 후속 적용 결과

Windows 글꼴 실험 파일 대신, 배포 가능한 픽셀 웹폰트 Galmuri11의 탭 문자 서브셋을 적용했다. 원본 글꼴로 식별했다는 의미는 아니다. [제작자 저장소](https://github.com/quiple/galmuri) · [로컬 자산 정보](../assets/fonts/README.md)

탭 라벨은 HTML 텍스트를 유지하며 `6px / 9px`, `letter-spacing: 0`, `scaleX(0.92)`를 사용한다. 가로 배율은 대체 폰트의 폭 보정이고 당시 CSS 값으로 추정한 것이 아니다. 31px 탭 박스와 세로 배치는 그대로다. 본문·제목·상단 메뉴의 폰트는 변경하지 않았다.

같은 R > 100 기준의 가시 획 측정 결과:

| 라벨 | 변경 전 폭 | 변경 후 폭 × 높이 | master 폭 |
| --- | ---: | --- | ---: |
| 프로필 | 20px | 16 × 6px | 약 16px |
| 다이어리 | 26px | 22 × 6px | 약 22px |
| 쥬크박스 | 26px | 22 × 6px | 약 21px |
| 사진첩 | 20px | 15 × 6px | 약 16px |

이 결과는 외형 치수의 개선이다. 개별 획 모양이 원본과 완전히 같다는 뜻은 아니다. 로컬 파일 모드, 기준 크기·데스크톱·좁은 화면에서 웹폰트 로딩과 기존 골격 검증을 다시 확인했다. [현재 화면](verification/step4/579x349.png)
